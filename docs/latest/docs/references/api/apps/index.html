POST /apps.assign_instance_static_route​

Description​

Bind a running instance to a chosen static route, in place — the instance is
never restarted. The gateway rebinds the instance's serving task on its next
discovery cycle, so traffic moves to the static route within seconds and the
same instance id is returned. The route is also stored as the instance's
static_route launch param so the binding survives a later restart. Fails if
the instance has no routable running task (nothing a gateway serves or can
serve). Publishing the route as a url-app tile is a separate step
(routers.publish_route_app). Tenant-admin only.

POST /apps.create_from_app​

Description​

Create a new tenant-owned application by cloning an existing application. The
source app's latest-version template and info are copied verbatim, so the clone
launches with the source's own defaults. The clone is independent of the source
(changing/deleting the source has no effect). The source may be any app the
caller can see (a global catalog app or a tenant app); a customization can't be
cloned directly — clone its base app. Tenant-admin only.

POST /apps.enable​

Description​

Enable or disable an app version. Extended with PMC-specific behavior:
single_active enforces one-active-version-per-app, confirm_stop drives warn-
then-confirm-then-terminate on undeploy when running instances exist, and
force drives the dry-run-then-confirm flow when a new version would conflict
with existing customizations.

POST /apps.upload_custom_app​

Description​

Install a custom app from a JSON payload (no archive), register it as managed
by the generic controller, and deploy it — in one call. Ownership is scoped by
the caller's role: a non-system caller (admin or AI-builder user) installs a
TENANT-OWNED app — scoped to the caller's company, stamped with the creator,
and deployed only to that tenant (the forced My Apps category keeps it
personal: creator + tenant admins); a system/root caller installs a GLOBAL app
deployed to all tenants. The category is always forced to My Apps (the
.app.conf's own category is ignored). The payload carries base64-encoded
contents: config (the .app.conf text), named assets (status icons / icon
/ no_info_html / extra files), and execution_files written to disk by the
launcher when the app starts (total size is capped). The .app.conf's own
icon / no_info_html and any embedded code are ignored — they come from this
payload. Re-uploading the same app_id updates the template and re-registers the
controller, but only the owning tenant may do so — another tenant is rejected.

Parameters​

Bodyrequest
required		request bodyrequest

request

assets
optional		App assets, base64-encoded. The five status_icon_* are all-or-nothing.assets
config
required		Base64 of the app's .app.conf text. Required.string
enable
optional		If set to true then the newly uploaded apps are enabled. Applies to app
